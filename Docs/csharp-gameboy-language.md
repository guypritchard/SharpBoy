# C# to DMG language contract (v0)

## Scoped direct-OAM sprite extension (milestone 10)

`GB.Sdk.GameSprites.Initialize()` loads a caller-supplied 8×8 2bpp tile as tile 4, clears/hides all
40 OAM entries, sets OBP0/OBP1 to `$E4`, and enables the OBJ bit while preserving
other LCDC bits (including LCD enable/disable). `Set(byte index, byte oamX, byte oamY,
byte attributes)` writes raw OAM Y, X, tile 4, attributes in that order. Raw bytes
mean visible position `(oamX - 8, oamY - 16)`; there is no hidden screen clipping or
bounds conversion. `Hide(byte index)` writes OAM Y = 0. The index must be a C#
compile-time byte constant 0..39, attributes a compile-time byte constant with
bits 3..0 clear (DMG bits 7..4 only); otherwise `GBL010` rejects the call, including
calls in unreachable submitted methods. X and Y can vary at runtime. Recognition
requires exact SDK assembly, marked method, type and signature; spoofed game methods
remain ordinary calls. Host intrinsics throw. Ordered observable typed `IrSprite`
operations reject malformed index/attributes/types/coordinates at verification.
Direct OAM writes wait for LY 144-152 if LCD is on; entry during LY 153 is
deferred through frame restart to the next VBlank. LCD-off calls do not wait.
Interrupts remain disabled. OAM DMA and its bus blocking/timing are deferred; this
does not assert hardware timing fidelity. See [the sample](../Samples/Sprites/README.md).

This is the **validated v0 native-ROM language**, with a scoped opt-in MBC1 asset extension below. The CLI checks Roslyn errors first, validates the subset, lowers typed IR, generates SM83 assembly and uses RGBDS 0.9.0 to build a DMG ROM-only cartridge by default (or a no-RAM MBC1 asset cartridge when explicitly requested). `GameIrCompiler.AnalyzeAndLower` exposes verified IR; `RomCompiler.CompileAsync` builds and independently validates the ROM. A valid C# program is not necessarily a valid game program. Source files are supplied explicitly; host framework references permit binding, not target library calls. Every declaration and operation in every submitted source file is checked, regardless of entry-point reachability. See [toolchain and CLI instructions](csharp-gameboy-toolchain.md).

## Explicit display inputs

Artwork is a build input, not part of the language or generated by the compiler.
`GameDisplay.InitializeBackground()` requires paired `--background-tiles` (64 bytes,
four DMG 2bpp tiles) and `--background-map` (1024 bytes, IDs 0..3).
`GameSprites.Initialize()` requires `--sprite-tiles` (16 bytes, copied as tile 4).
The API equivalent is `RomBuildOptions.Assets = new GameAssetBundle(...)`, which
defensively copies its byte-array inputs. Missing, half-paired, wrong-size,
out-of-range map and unused inputs fail with `GBC009`; no artwork is substituted.
Requirements follow initialization operations in the lowered entry-reachable IR.
`SetScroll`, `WaitForNextVBlank`, and sprite `Set`/`Hide` alone need no assets.
Sample artwork lives in [Samples/Assets](../Samples/Assets/README.md).

## Entry point and declarations

Exactly one method explicitly marked `[GameEntryPoint]` must exist across all source files. It is `static void`, parameterless, non-generic, and belongs to a static class; the entry must have a block body (not an expression body). The attribute is the resolved `GB.Sdk.GameEntryPointAttribute` from the actual SDK assembly; a method named `Main` or a lookalike attribute is not an entry point. All game methods are static, non-generic and directly called; only recursion reachable from the entry (including mutual recursion) is forbidden. Unreachable cycles are allowed if all their declarations and operations pass validation. Helper methods require a block or expression body; extern and declaration-only methods are unsupported even when unreachable. The public `FrontendResult.ReachableCalls` graph contains entry-reachable methods only, although all submitted methods are validated. Static classes may contain methods, `const` fields and static fields of supported types. No instance state exists. Method parameters and return values may use the supported types (including `void` returns); no reference returns or `ref`, `out`, `in`, `params` or optional parameters. A `const` must be a compile-time C# constant of a supported type. Static fields may be uninitialized or initialized with a compile-time C# constant of the declared type, including allowed constant numeric conversions; the initializer expression must also use only supported operators (so `2 * 3` is rejected). `readonly`, `volatile`, static constructors, dynamic initializers and C# beforefieldinit side effects are not supported. Only ordinary access modifiers (`public`, `internal`, `private`) and required `static`/`const` modifiers are permitted on class members; other modifiers and attributes are unsupported.

| Area | Supported v0 target examples | Rejected examples | Reserved diagnostic |
| --- | --- | --- | --- |
| Entry | `[GameEntryPoint] static void Start() { }` in a static class | no entry, two entries, `static int Start()`, instance entry | GBL001 |
| Types | `bool`, `byte`, `sbyte`, `ushort`, `short`, `int` intermediates and corresponding static storage/parameters/returns | `long`, `uint`, `char`, `float`, `string`, nullable, pointers, arrays, structs, enums | GBL002 |
| Declarations | `static byte counter = 3; const short Limit = 10; static int Add(int a, int b) => a + b;` | instances, properties, events, generic methods/types, local functions, lambdas | GBL003 |
| Static initialization | `static byte count; static short limit = -2;` | `static byte count = Read(); static Store() { count = 1; }` (a static constructor) | GBL004 |
| Statements | blocks, local declarations with/without initializer, expression statements for assignments/calls, `if`/`else`, `while`, `return`, `break`, `continue` | `for`, `foreach`, `switch`, `do`, `goto`, `using`, `try`/`throw` | GBL005 |
| Expressions | literals/constants, reads of locals/parameters/static fields, parentheses, direct calls, `=`, `+=`, `-=`, `&=`, `|=`, `^=`, unary `+`, `-`, `~`, `!`, `++`, `--`, binary `+`, `-`, `&`, `|`, `^`, `==`, `!=`, `<`, `<=`, `>`, `>=`, `&&`, `||` | `*`, `/`, `%`, shifts, conditional `?:`, `??`, interpolated strings, object creation, indexing | GBL006 |
| Conversions | C# implicit numeric promotions and explicit numeric casts among supported numeric types in unchecked context | checked conversions/arithmetic, casts to unsupported types, user-defined conversions | GBL007 |
| Calls and runtime | resolved direct game-method calls and explicitly approved SDK intrinsics | recursion, virtual/interface/delegate calls, `Console.WriteLine`, boxing, implicit runtime helpers | GBL008 |

Diagnostics are stable **categories**: `GBL001`-`GBL008` denote the original unsupported constructs, and `GBL009` rejects nonconstant bank-operation arguments; use a source file/line/column on every source-related diagnostic. Roslyn's own `CSxxxx` errors (including definite assignment, invalid constant conversions and type errors) are reported first and are never reinterpreted as supported features. No ROM may be emitted on any error. Later memory/resource diagnostics are separate from language diagnostics.

## Numeric and evaluation rules

`bool` is distinct from numbers. `byte` and `sbyte` are 8-bit, `ushort` and `short` are 16-bit, and C# `int` is **32-bit signed**, even on the 8-bit SM83. The C# usual integral promotions apply: small integer operands commonly promote to `int`, including `ushort` arithmetic. For example, `int n = (ushort)65535 + 1;` yields 65536, not zero; `byte b = unchecked((byte)n);` yields 0. The compiler must perform approved arithmetic, bitwise and comparisons at the promoted width, narrowing only where equivalent under C# semantics. `int` addition/subtraction and unary negation wrap modulo 2^32 in unchecked context; explicit narrowing uses the low 8 or 16 bits (with signed interpretation for `sbyte`/`short`). Neither silently substitute 8/16-bit operations for 32-bit intermediates nor support multiplication/division/remainder just because Roslyn accepts them. `checked` statements/expressions and a build option that enables checked arithmetic are unsupported; `unchecked` is accepted only around an explicit numeric cast. `++`, `--`, `+=`, `-=`, `&=`, `|=`, `^=` are supported on assignable primitive locals, parameters and static fields with C# evaluation and narrowing behavior; other increment/compound forms are unsupported.

Evaluate receivers/arguments and operands left-to-right, each exactly once, preserving side effects even if an expression result is discarded. `&&` and `||` short-circuit; `&` and `|` on booleans evaluate both operands. Signed comparisons interpret `sbyte`, `short`, and `int` as signed after C# promotions; equality and relational comparisons follow the C# converted operand types. Assignment evaluates the target location before the right-hand side and yields the assigned value; compound assignment follows C# conversion rules, including its implicit narrowing. Locals require C# definite assignment before use. Uninitialized static fields and permitted constant initializers have the values described in the ABI.

```csharp
using GB.Sdk;

static class Game
{
    static byte Counter = 2;

    [GameEntryPoint]
    public static void Start()
    {
        int promoted = Counter + (ushort)65535;
        if (promoted > 65535 && Counter != 0)
            Counter = unchecked((byte)promoted);
        while (Counter != 0) Counter--;
    }
}
```

This example is within the native-ROM subset. Approved intrinsics are `GB.Sdk.GameMemory.WriteByte(ushort, byte)` and `GB.Sdk.GameDisplay.InitializeBackground()`, `WaitForNextVBlank()`, `SetScroll(byte x, byte y)`. Recognition requires the resolved SDK **assembly, declaring type, exact non-generic static void signature and SDK intrinsic marker**; namespace/name lookalikes are ordinary game methods only when their own declarations satisfy the subset. Invalid external or host calls are rejected. Host SDK method bodies throw and never become target code. These operations lower to ordered observable `IrWriteByte`/`IrDisplay` instructions (LCD reads, VRAM transfers and register writes cannot be optimized away). Initialization safely disables an enabled LCD at VBlank, copies the supplied background while off and enables BG last. The polling wait first observes the end of any current VBlank and then the beginning of the next; it requires the LCD to be enabled, uses neither interrupts nor HALT, and will not return with LCD off. The scroll API writes SCX then SCY. See the [sample](../Samples/ScrollingBackground/README.md).

C#'s numeric promotions mean relational comparisons on the approved unsigned 8/16-bit types generally run at signed 32-bit width after zero extension; the IR exposes both the conversion and comparison signedness. All validated static fields (including unreachable declarations) are retained deterministically, while `const` references lower to literals. Arbitrary host methods are never copied into the cartridge. Arrays, heap allocation, strings, exceptions, generics, reflection, async, user interrupts and banking remain out of scope. Future extensions must amend this contract and add semantic and ROM tests first.

**Asset-only MBC1 extension (2026-10-17):** the last sentence above describes the original v0 contract; banking now has one narrow exception. With an explicit 4/8/16/32-bank no-RAM MBC1 profile, `GB.Sdk.GameBanking.CopyToBuffer(byte bank, ushort sourceAddress, ushort bufferOffset, ushort length)` and `ReadBufferByte(ushort bufferOffset)` are SDK-resolved intrinsics, not arbitrary same-name methods. Their arguments must be compile-time constants (including `const` expressions), not mutable locals; otherwise `GBL009` is reported. Copy length must be positive and wholly inside one declared physical bank-2+ asset and the `$D000-$D7FF` staging range; read offset must be inside that range. Invalid spans or use without MBC1 fail compilation (`GBB007`); malformed manifest options fail (`GBC008`). The copy restores the runtime-tracked previous bank and reads take place after copies in source order. Compiler/runtime exclusively own MBC1 mapper registers: raw `GameMemory.WriteByte` requires a statically provable address and rejects ROM/control `$0000-$7FFF`, staging `$D000-$D7FF`, mapper state, allocated slots, stack and their WRAM echoes (`GBB007`). Use fixed safe WRAM destinations such as `$C100`; ROM-only raw writes retain their original behavior. No restoration guarantee applies to arbitrary external mapper writes. Bank 1 remains reserved for display data, code/helper are ROM0, interrupts remain disabled. This does **not** add managed arrays, function banking, save RAM, >32 banks, VRAM/DMA transfers or reentrancy. The rest of the original subset remains unchanged.
